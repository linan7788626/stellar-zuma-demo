# 首轮设计：统一赫罗图与读图练习闭环

## 状态与范围

用户已同意优先推进上一轮建议中的三项：统一赫罗图、暂停放大阅读、三类读图题，并形成一次完整闭环。本文件将这些目标收敛为可实现、可验收的首轮方案；具体交互和工程安排为建议，待确认后实施。

本轮不展开全部四阶段路线，不重写祖玛物理，不新增框架、构建工具、运行依赖、在线账户或数据上报。已有 17 课、无尽入口、收集规则和过关问答继续保留。仍支持直接打开 `index.html`。

## 1. 要解决的问题

- 迷你图、关卡图和演化图采用不同绘图逻辑与坐标约定；难以保证读图、点选与动画一致。
- 当前图主要用于展示学习进度，缺少可暂停、可比较、能获得解释的阅读过程。
- 科普目的需要学生根据温度和光度推理，而不只是记住球色。

交付两条闭环：

1. **学习闭环**：提出读图问题 → 观察甲/乙示意星 → 作答 → 基于坐标的解释 → 换一组应用 → 返回游戏。
2. **工程闭环**：明确设计 → 实现 → 真实浏览器回归 → 独立审查 → 修正 → 文档与可复现演示步骤。

首轮证明功能和交互成立，不声称已经通过学生实验证明教学效果。

## 2. 统一的科学模型

### 坐标与单位

- 横轴为表面温度 T（K），使用对数刻度，左热右冷。
- 纵轴为光度 L/L☉，使用对数刻度，下暗上亮。
- 全部图共用同一物理范围与投影：本轮采用 T=2,500–100,000 K，L/L☉=10⁻⁴–10⁶；不同画面仅改变边距、信息密度和高亮。
- 太阳参照点取 T=5772 K、L/L☉=1、R/R☉=1；这是用于换算的参照，不暗示所有例星数据具有同等精度。
- 等半径线依据 `L/L☉ = (R/R☉)² × (T/5772 K)⁴` 计算，不再采用手写的归一化斜率。
- 无效的非正温度/光度不得进入对数运算；越界点采取明确的裁切/标记策略，不用静默更改数据伪造位置。

### 数据含义

- 光谱主序点、区域边界和演化路径使用显式温度/光度数据，标注为教学代表点或示意路径，不冒充旁边例星的观测数据。
- 真实例星名称与其温度型/演化状态的说明保持现有纠正结果；本轮不承诺建立完整实测星表。
- 演化仍是简化路径，节点间的动画时长不表示真实持续时间；行星状星云阶段的点表示中心星。
- 所有视图明确区分“坐标可读”与“路径是教学示意”。小图可省略密集刻度及半径数值，大图保留轴单位、参考刻度和太阳锚点。

### 首轮教学数据与责任

以下数值是本方案选择的教学代表点，不是旁边真实例星的测量值。图表实现专员负责录入、保持单位与范围正确，并在实现文档记录所有区域/路径数据；审查者核对物理关系与标注。本轮不等待另行批准实测数据集，也不通过反算旧归一化位置生成伪物理数据。

| 光谱代表点 | T/K | L/L☉ |
| --- | ---: | ---: |
| O | 35,000 | 100,000 |
| B | 18,000 | 800 |
| A | 8,500 | 20 |
| F | 6,500 | 3 |
| G / 太阳参照 | 5,772 | 1 |

类太阳简化路径的 `(T, L)` 节点采用：`(5772,1) → (5500,10) → (4200,100) → (3200,2000) → (30000,2000) → (100000,100) → (20000,0.01)`；现有四个课程阶段对应第 0、2、4、6 个节点。大质量简化路径采用：`(35000,100000) → (30000,150000) → (20000,200000) → (8000,200000) → (3500,200000)`；现有三个阶段对应第 0、2、4 个节点。这些数值只用于方向与数量级教学，不声明来自某条恒星演化数值计算。

## 3. Module 与 Interface

采用按顺序加载的普通脚本，保持 `file://` 可用。建议新增两个高内聚 Module，不同时拆分整个游戏：

### 赫罗图 Module

隐藏共享目录、物理投影、太阳/半径换算、坐标轴、区域、轨迹、DPR 绘制和命中检测。

- 面向调用方的主要 Interface 为“把场景画到指定 canvas”和“根据指针坐标返回选中的点/区域”。
- 场景只传当前目标、已有进度、可选演化动画位置、练习比较星、显示密度；Module 不读写游戏状态或存档。
- 纯模型换算与教学数据可被练习 Module 使用，避免题目答案与绘图各自维护一套物理规则。
- 标题选关必须复用同一投影与绘图布局，不能保留旧的百分比命中坐标。
- 游戏中仅保留组装场景的 Adapter；旧的三套绘图 Implementation 应被替换，而不是叠加第四套。
- 演化过关动画使用同一图中路径和模型，不因更换绘图而丢失既有行为。

### 读图练习 Module

隐藏三类题目的情境、正确选项、解释、换题顺序及本次练习计数。

- Interface 支持取得当前题、作答、换题/切换题型及读取本次结果。
- 单题重复点击只能计分一次；换题确实改变例子或甲乙位置，正确答案不固定在第一个按钮。
- 练习结果与游戏分数、课程点亮、最高解锁关卡完全分离。首轮保留本次页面会话内的作答情况；不扩展存档格式或声称形成长期掌握档案。
- DOM 和 Canvas 交互由展示层处理；题目逻辑不依赖浏览器事件。

## 4. 暂停放大阅读

在现有学习栏加入明确的“放大赫罗图 · 读图练习”按钮，提供 H 快捷键。主屏两栏布局继续使用。

标题、介绍、暂停、过关、失败卡片会遮住学习栏，因此这些卡片在原主操作之后统一提供次级“读图练习”按钮（非 primary 样式），保证触屏也能进入。所有原游戏状态均可开启；标题/失败画面未指定活动课时以太阳与主序带为阅读参照，不改变所处状态。

采用独立的阅读/练习对话层，不销毁承载标题、介绍、暂停和过关问答的原覆盖层。对话层包含图表、三类题型、问题、选项、解释、换题与关闭操作。

### 状态契约

- 打开时释放加速并冻结游戏更新，包括星链、发射、技能计时及过关/失败动画。关闭后保留打开前的状态。
- 从游玩中打开，正常关闭可回到游玩；从暂停、介绍或过关状态打开，关闭后不能跳过原流程。
- 阅读期间若页面失焦/隐藏，关闭阅读层后不得意外恢复正在运行的游戏；应保持暂停，等待用户继续。
- 阅读期间游戏键与指针不穿透；Esc 只关闭阅读层，不同时触发游戏暂停切换。
- 原过关问答的选项、答案反馈和“下一关”是否解锁，在开关阅读层前后保持一致。

实现时使用独立的阅读冻结标志，不把所有来源状态改写成 `paused`。冻结门必须覆盖 `update()` 以及 `frame()` 内独立推进的演化 `track.t` 分支。主键盘处理器在阅读层打开时先分流/返回，涵盖 Space/X/F/P/Esc/Enter 等全部底层动作；失焦时只将原来游玩中的底层状态变为暂停，其余介绍/问答/终末动画状态保留。

### 可访问性与布局约束

- 明确的对话框语义、关闭按钮、焦点限制与焦点返回；键盘可完成作答和换题。
- 甲/乙标签避免与 A/B 光谱型混淆，且不只依赖颜色；提供等价的文字/数值图表摘要。
- 大图的主要轴标签与问题保持可读；窄屏纵向排列、无横向溢出，内容可滚动，关闭与主要操作可达。
- 桌面图表优先占用空间；宽度不足以容纳图表和题目两栏时改为单栏，不用固定最小宽度撑破对话框。
- 设计专员建议以对话框内容宽 720px 为两栏阈值：图表使用 `minmax(0,1fr)`，题目栏约 300px；低于阈值改为图表在前、题目在后的单栏。最终尺寸由设计专员依据实际内容验证，但不能同时施加相互矛盾的固定最小列宽。
- 首轮只提供三类题型，不额外增加混合模式、排行榜或复杂的图层开关。

## 5. 三类读图题

题目中的甲/乙均标注为练习示意星。优先采用两星比较，突出相关证据；本关目标仍可作为次要参照，但不能混淆题目对象。

| 题型 | 要掌握的关系 | 反馈必须包含 |
| --- | --- | --- |
| 温度比较 | 横轴左热右冷；颜色只是提示 | 甲乙左右位置、温度方向、据此判断 |
| 光度比较 | 纵轴下暗上亮；不是地球上看到的视亮度 | 甲乙上下位置、L/L☉ 的意义 |
| 半径推理 | 同温时 L∝R²；热而暗不等于巨大 | 题设条件、图上证据、半径结论 |

每类至少两个不同例子，包含交换甲乙后正确选项改变的情形。半径题优先选用无需复杂计算的同温比较，另可用白矮星与太阳作为迁移例。

作答后给出正确答案和解释；错误选项反馈点出误区。提供“换一组”继续练习。统计写作“本次答对 / 已答”，不把“已练习”写成“已掌握”，也不声称现有通关问答能够证明掌握。

## 6. 验证与分工

| 关键结论 | 最小证据 | 验证负责人 |

验证预算：实现专员各自运行所属最小测试；整合所有写入后主会话运行一次完整套件、语法检查和差异检查。只有审查发现缺陷或随后改动相关代码时，才补充或重复相应验证。浏览器使用已有隔离 Chrome/CDP harness，不安装自动化运行依赖。

交付文档包含：功能说明、科学模型与来源、操作入口、演示步骤、回归结果以及仍需真人学生验证的教学效果。代码审查发现的问题需有明确处置与复验记录。
